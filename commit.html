掌握提交专题

把“保存代码”升级成“留下清晰历史”：用多张图和小练习学会 status、diff、add、commit。

先建立概念

一次提交不是随手保存，而是一次有意义的项目快照

掌握提交的关键是“四步确认”：看状态、看差异、选内容、写说明。你不需要一次学会所有命令，只要先把这条主线练熟。

四步上手

跟着这四步做，每次提交都会更稳

01

看状态：我改了什么？

运行 git status，先确认哪些文件被修改、哪些文件还未跟踪、哪些文件已经暂存。

02

看差异：改动对吗？

运行 git diff 检查工作区差异；暂存后再用 git diff --staged 检查即将提交的内容。

03

选内容：只提交相关修改

用 git add 文件名 精准暂存；如果一个文件里有多处无关修改，可以用 git add -p 分块选择。

04

写说明：让未来的你看懂

提交信息写“这次做了什么”，例如 docs: add commit practice guide，不要只写 update。

图解 commit

commit 里面到底有什么？

把 commit 当成“带说明的快照”

每个 commit 都有唯一编号、作者、时间、提交信息和文件快照。Git 正是靠这些快照，把项目历史串成可追踪的时间线。

为什么要小步提交

好的历史来自很多小而清楚的提交

小步提交更容易回退和审查

如果一个提交里同时改样式、修 bug、加功能，排查问题时会很痛苦。把不同目的拆成多个提交，团队成员更容易读懂你的思路。

提交信息模板

写出别人愿意读的提交信息

推荐格式

type: 简短说明

例如：feat: add Git commit lesson page

常见 type

feat 新功能、fix 修复、docs 文档、style 样式、refactor 重构。

避免这样写

不要只写 update、change、fix，这些词太笼统，过几天就看不懂。

动手练习

10 分钟练会一次完整提交

练习任务

  • 新建 notes.md，写 3 条 Git 学习笔记。
  • 运行 git status，确认文件处于未跟踪状态。
  • 运行 git add notes.md，再运行 git diff --staged 检查暂存内容。
  • 运行 git commit -m "docs: add git learning notes" 创建提交。
  • 运行 git log --oneline -3，确认历史中出现这次提交。

记忆口诀

先 status 看全局，再 diff 看细节；add 是选择，commit 是定稿。

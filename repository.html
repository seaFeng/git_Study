理解仓库图解专题

用 4 张图把工作区、暂存区、本地仓库、远程仓库和常见文件状态一次讲清楚。

第一步

先建立整体地图

把 Git 想成一个“快照管理系统”：你先在工作区改文件，再把想保存的变化放进暂存区，最后提交到本地仓库；需要协作时再推送到远程仓库。

第二步

四个区域分别负责什么？

01

工作区

你能在编辑器里直接看到和修改的项目文件。这里的变化还没有被 Git 正式保存。

02

暂存区

一次提交的候选清单。运行 git add 就是在挑选哪些变化要进入下一次提交。

03

本地仓库

保存在你电脑里的提交历史。运行 git commit 后，暂存区内容会变成一个可回溯的快照。

04

远程仓库

托管在 GitHub、GitLab 等平台上的共享仓库。运行 git push 后，团队成员才能看到你的提交。

第三步

再看文件状态如何流转

读懂 git status 的关键

当 Git 提示 untracked、modified、staged 时，它是在告诉你文件处于哪个阶段。养成频繁运行 git status 的习惯，可以避免误提交和漏提交。

第四步

把仓库概念放回真实协作

推荐工作节奏

每天开始先同步远程代码；新任务创建独立分支；开发过程中小步提交；完成后推送分支并发起代码评审。

练习清单

跟着做一次就能记住

仓库理解练习

  • 运行 git status，观察当前分支和文件状态。
  • 新建一个文件，先不要 add，再运行一次 git status。
  • 运行 git add 文件名，观察它如何进入暂存区。
  • 运行 git commit -m "practice repository zones"，确认变更进入本地仓库。

一句话总结

工作区负责“改”，暂存区负责“选”，本地仓库负责“存”，远程仓库负责“共享”。
